# StreamFetch 1.6.1 — Clean desktop shutdown

_Released 2026-10-22_

## In one sentence

Closing the desktop window now stops its owned server and native helper
processes, including speech-engine helpers that outlive the main bootloader.

## Visual tour

![The unchanged StreamFetch 1.6 listening and search interface](../assets/releases/v1.6.0/product-tour.gif)

This is a lifecycle-only patch. The actual 1.6 screenshots remain representative;
all smart-library, local-search and home-player features are retained.

## What changed

### Fixed

- Desktop servers start in their own process session on macOS/Linux. Closing
  the window terminates that owned group and cleans up surviving helpers.
- Windows shutdown targets the launcher's exact process tree using the system
  `taskkill` executable, never every Python or StreamFetch process by name.
- Added a real process-tree regression test with a helper that deliberately
  ignores graceful termination, plus targeted platform dispatch tests.

## Upgrade notes

No media, settings or library migration is needed. Install 1.6.1 in place of
1.6.0. Existing local libraries, transcripts, source subscriptions and backups
remain in their existing directories. Background work interrupted by closing
the app follows the existing explicit restart/retry behavior.

Home sharing remains opt-in, read-only and intended for trusted home HTTP
networks only. See the [1.6 upgrade notes](v1.6.0.md#upgrade-notes) for the full
model, metadata-backup and network boundaries.

## Verified with

- Local suite: 129 passed, one optional FFprobe integration skipped; 80% measured coverage.
- Targeted process-group, Windows-command and helper-dispatch tests.
- A real POSIX parent/helper termination test using a local listening socket.
- Full validation suite and platform build workflows.
- Interactive Windows startup/close testing remains deferred to the user.
